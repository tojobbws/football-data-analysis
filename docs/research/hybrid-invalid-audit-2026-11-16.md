# ตรวจสอบคำตอบ AI ที่ถูกตีตก (INVALID) ของ Hybrid AI

วันที่ 2026-11-16 · ตรวจสอบอย่างเดียว ไม่แก้โค้ด prompt หรือฐานข้อมูล ไม่เรียก AI และไม่อ่านผลการแข่ง
สคริปต์: `scripts/research/invalid-audit.ts` · ผลละเอียด: `reports/invalid-audit/report.json`

## สรุปสั้น

- **ตัวเลขรวม:** ตรวจคำตอบ AI ทั้งหมด **1,560 ครั้ง** (742 decisions, engine `hybrid-ai-v1` ทุก prompt version) ถูกตีตก **151 ครั้ง (9.7%)**
  - 148 ครั้งโดน **number guard**
  - 3 ครั้งโดน **คำต้องห้าม**
  - ไม่มีกรณีที่ผิด schema, ฝั่งไม่ตรงกับตลาด, เส้นไม่ตรง หรือเลือกตัวเลือกที่ไม่มี เพราะ structured output บังคับโครงสร้างไว้แล้ว
- **v2.0 แย่ลงอย่างเห็นได้ชัด:** ตีตก **51/111 ครั้ง (46%)** เทียบ v1.6–v1.9 ที่อยู่ราว 0–6%
- **สาเหตุหลัก:** ตัวเลขที่ถูกตีตก 153 จาก 172 ตัว (89%) เป็น **ค่าที่ AI คำนวณเองถูกต้อง** เช่น xG ได้ + xG เสียของนัดเดียวกัน ("xG รวม 4.01") หรือประตูได้เฉลี่ย + ประตูเสียเฉลี่ย ไม่ใช่ตัวเลขที่แต่งขึ้นมาลอยๆ ตามกฎ "AI ห้ามสร้างตัวเลข" การตีตกถือว่า**ถูกต้อง** เพราะ guard ตรวจไม่ได้ว่าบวกลบถูกหรือไม่ แต่ป้องกันได้ด้วยการปรับ input หรือ prompt
- **false positive ของ guard จริงๆ มีน้อยมาก:**
  - 1 กรณีปัจจุบัน: "1,474" (ค่า Elo) ถูก guard อ่านเป็น 1.474
  - 13 กรณีในอดีต: "14 วัน" ใน v1 ซึ่งแก้ไปแล้วใน v1.1
- **การถามซ้ำไม่ช่วย:** ระบบถามซ้ำด้วยข้อมูลเดิมโดยไม่บอกว่าผิดตรงไหน จึงมักผิดซ้ำ ใน 33 ครั้งที่ถามซ้ำแล้วยังตก มีถึง 31 ครั้งที่ผิดตัวเลขเดิม
- **ผลกระทบ:**
  - มี 16 decisions ที่จบเป็น INVALID ครอบคลุม 13 คู่-รอบ
  - 10 คู่-รอบได้ pick ช้าไป 50–117 นาที
  - 3 คู่ไม่ได้ pick เลย คือ Türkiye v Belgium, Central African Republic v Benin และ Trinidad and Tobago v Antigua and Barbuda
  - **วันนี้คู่น่าจับตาต้องรอไปถึงรอบ 16:05 ก็เพราะเรื่องนี้**

## 3. ตัวเลขที่ถูกตีตกมาจากไหน (172 ตัว)

ไล่ทุกตัวเทียบกับ input ที่เก็บไว้ (สิ่งที่ AI เห็นจริง) โดยเช็กเฉพาะการคำนวณที่มีความหมายในเชิงฟุตบอล และนับว่าตรงเมื่อตรงตามจำนวนทศนิยมที่ AI เขียน

| ที่มา | ทั้งหมด | ใน v2.0 | ตัวอย่าง |
|---|---|---|---|
| **ผลรวมของนัดเดียว** (xG ได้+เสีย, ประตูได้+เสีย) | 68 | **48** | "xG รวม 4.01", "xG รวม 3.17", "xG รวมของสองทีม 2.31" (3.57 = 1.71+1.86) |
| **ผลรวมของช่วงฟอร์ม** (ค่าเฉลี่ยได้+เสีย, ค่าเฉลี่ย×จำนวนนัด) | 71 | 2 | "ค่าเฉลี่ยประตูรวมในเกมเหย้า 4.4", "xG รวมเฉลี่ย 2.97" |
| ผลต่างระหว่างสองทีม (แต้ม) | 6 | 0 | "ห่างกัน 17 แต้ม" |
| ผลต่างภายในช่วงฟอร์ม (xG ได้−เสีย ฯลฯ) | 5 | 0 | 0.38 = xg_for_avg − xg_against_avg |
| ผลรวมของสองทีม | 3 | 0 | 2.71 = xg_for_avg เหย้า + เยือน |
| ตัวเลขใน prompt ที่ไม่มีใน input | 13 | 0 | "14 วัน" (v1 เท่านั้น) |
| ลอกตัวเลขผิดหรือปัดผิด | 2 | 1 | 43 (input 43.7), 102 (input 101) |
| ตัวคั่นหลักพัน | 1 | 1 | "1,474" (Elo 1474) |
| หาที่มาไม่ได้ | 3 | 0 | "50" ×2 (น่าจะปัดลง 50.643% เป็น 50), "4.10" |

**ตัวอย่างข้อความจริง (v2.0):**

- Central African Republic v Benin: *"…นัดล่าสุดมี 5 ประตูและ xG รวม 4.01…"* ทั้ง 3 คำตอบเขียนตัวเลขนี้ ทั้ง attempt 1 และ 2
- Canada v Guatemala: *"…นัดล่าสุดมีประตูรวม 5 ลูก และ xG รวมของสองทีมอยู่ที่ 3.17…"* ทั้ง 3 คำตอบ
- Trinidad and Tobago v Antigua: *"…เกมล่าสุดมี xG รวม 2.31 ซึ่งต่ำกว่าเส้น 3.5…"*

**ทำไม v2.0 ถึงพุ่ง (สมมติฐาน ยังไม่ได้พิสูจน์):**

1. guide ของ v2.0 พูดถึง "total goals" และ `xg_total_vs_closing_line` (xG รวมลบเส้นปิดราคา) ทำให้ AI อยากพูดถึง "xG รวมของนัด" แต่ input ไม่มีค่านี้ตรงๆ
2. ทั้ง 6 decisions ที่ตกวันนี้เป็นเกมทีมชาติที่มี xG แค่นัดเดียว (`data_quality` บอก "no xG for N recent matches") AI จึงยกนัดนั้นนัดเดียวมาเป็นหลักฐาน และรวมค่าเอง

## 4. ประเมิน false positive

| กลุ่ม | จำนวน | ตีตกถูกไหม | ป้องกันด้วย prompt/input ได้ไหม |
|---|---|---|---|
| ค่าที่ AI คำนวณเอง (ผลรวม/ผลต่าง) | 153 | **ถูกตามกฎ** คำนวณถูกจริง แต่ guard ตรวจเลขคณิตไม่ได้ ถ้ายอมให้ผ่าน ผลรวมที่คำนวณผิดก็จะผ่านด้วย | **ได้** ใส่ค่าที่คำนวณไว้แล้วใน input หรือสั่งใน prompt ว่าห้ามคำนวณเอง |
| "14 วัน" (v1) | 13 | false positive ของการออกแบบ input | แก้แล้วใน v1.1 (ใส่ค่า 14 ไว้ใน input) |
| "1,474" | 1 | **false positive ของ guard** อ่านตัวคั่นหลักพันเป็นจุดทศนิยม | แก้ที่ guard (เกิดขึ้นเพราะ Elo เป็นเลข 4 หลักที่เพิ่งเข้ามาใน v2.0) |
| ปัดผิด หรือลอกตัวเลขผิด | 2 (+"50" ×2 ที่น่าจะเป็นแบบเดียวกัน) | ถูก เพราะเป็นตัวเลขที่ผิดจริง | ช่วยได้บางส่วน |
| "4.10" | 1 | ไม่ทราบ ไม่มีข้อความประกอบเหลืออยู่ | – |
| คำว่า "กำไร" | 3 | ถูกตามกฎ แต่ 1 กรณีที่เห็นข้อความคือ *"อัตราไม่รวมค่ากำไร"* ซึ่ง AI ใช้แปล "no-vig" ไม่ได้ใช้ในความหมายการพนัน | **ได้** กำหนดคำที่ใช้แทน เช่น "ราคาที่ตัดค่าน้ำแล้ว" |

**ข้อจำกัด:** ระบบเก็บ raw output ไว้แค่คำตอบเดียวต่อ decision คือคำตอบสุดท้าย หรือคำตอบที่ชนะโหวต คำตอบที่ถูกตีตกระหว่างทางเหลือแค่ข้อความ violation (ตัวเลขกับเหตุผล) จึงยืนยันบริบทได้เฉพาะ decision ที่ INVALID ส่วนตัวเลขอื่นยืนยันจากที่มาใน input

## 6. วิธีแก้ขั้นต่ำที่แนะนำ (ยังไม่ได้ทำ รออนุมัติ)

ทุกข้อ **ไม่ปิดหรือผ่อน number guard** ตัวเลขทุกตัวที่ขึ้นเว็บยังต้องมีอยู่ใน input

| # | วิธี | แก้ที่ | ผล | ความเสี่ยง |
|---|---|---|---|---|
| 1 | **ถามซ้ำพร้อม feedback**: ตอนถามครั้งที่ 2 แนบข้อความว่า "คำตอบก่อนหน้าถูกตีตกเพราะตัวเลข 4.01 ไม่อยู่ใน input ให้ยกเฉพาะตัวเลขที่มีใน input และห้ามบวก ลบ หรือเฉลี่ยเอง" | `hybrid-job.ts` `askOnce` (prompt ครั้งแรกไม่เปลี่ยน) | แก้ปัญหาถามซ้ำแล้วตกซ้ำ (31/33) | คำตอบที่ถามซ้ำอาจเปลี่ยนฝั่ง ต้องบันทึกว่าคำตอบไหนมาจาก retry และถือเป็นการเปลี่ยน engine ที่ต้องตัดสินภายใต้การล็อก v2.0 (ADR 0020) |

| 3 | **input v2.1 ใส่ค่ารวมไว้ให้**: `goals_total`, `xg_total`, `npxg_total` ต่อนัด และ `goals_total_avg`, `xg_total_avg` ต่อช่วงฟอร์ม | `buildHybridInput` (`hybrid.ts`) | ตัดต้นเหตุหลัก (139 จาก 172 ตัว) | เปลี่ยน input จึงต้องขึ้นเวอร์ชันใหม่ ขัดกับการล็อก v2.0 (ต้องให้เจ้าของตัดสิน) และ input ใหญ่ขึ้นเล็กน้อย |

**ลำดับที่แนะนำ:**

- **ข้อ 1 + 3 + 4 รวมเป็นงานเดียว (v2.1)** ถ้าเจ้าของตัดสินใจเปิดการล็อก v2.0 ถ้ายังไม่เปิด ทางที่เปลี่ยนน้อยที่สุดคือข้อ 1 เพราะไม่แตะ prompt ครั้งแรกหรือ input

## 7. ความเสี่ยงและ test ที่ต้องมีก่อนแก้

- **guard (ข้อ 2):**
  - "1,474" ผ่านเมื่อ input มี 1474
  - "1,474" ตกเมื่อ input ไม่มีทั้ง 1474 และ 1.474
  - "1,5" และ "1.474" ยังทำงานเหมือนเดิม
  - คำต้องห้ามและเลขที่ไม่มีใน input ยังตกเหมือนเดิม
- **retry พร้อม feedback (ข้อ 1):**
  - ใช้ fake decider ให้ตอบผิดก่อนแล้วค่อยถูก ตรวจว่า attempt 2 ได้รับรายการ violation
  - attempt 2 ที่ยังแต่งตัวเลขต้องตกเหมือนเดิม
  - `votes` และ `violations` ยังบันทึกครบ
  - prompt ของ attempt แรกไม่เปลี่ยน (snapshot test)
- **input/prompt v2.1 (ข้อ 3–4):**
  - snapshot ของ input ใหม่ และค่าที่เพิ่มต้องคำนวณถูก (เช่น xg_total = xg_for + xg_against ตามทศนิยมที่เก็บ)
  - "xG รวม 4.01" ผ่าน guard เมื่อค่านั้นอยู่ใน input
  - `HYBRID_PROMPT_VERSION` ขึ้นเวอร์ชัน
- **ตรวจซ้ำแบบ dry-run:** replay 16 decisions ที่ INVALID และ 82 ที่ต้องถามซ้ำ ด้วย input เดิม แล้ววัดอัตราการตีตกกับการกระจายฝั่งเทียบ live **โดยไม่ใช้ผลแพ้ชนะ**
- **production:** หลังแก้ ให้ดูอัตราการตีตกของรอบ 14:00 สัก 3–5 วัน เป้าหมายคือกลับไปอยู่ในระดับ v1.6–v1.9 (≤ 6%)
